## Entry points

| نقطة الدخول | من يستخدمها | ما يحدث |
|---|---|---|
| `https://clinicsyseg.com/` | كل المستخدمين | الموقع الرئيسي: تعريف مختصر + زر «تسجيل الدخول» + توضيح أن النظام يعمل بدعوة فقط |
| `https://{slug}.clinicsyseg.com/` | موظفو عيادة | تحل الواجهة الـ slug؛ إن لم يكن مسجلًا تظهر صفحة الدخول باسم العيادة |
| `https://admin.clinicsyseg.com/` | Super Admin فقط | لوحة إدارة المنصة بعد مصادقة قوية |
| رابط الدعوة في البريد | مستخدم مدعو | `https://<slug>.clinicsyseg.com/?invite=<token>` → S03 تعيين الاسم وكلمة المرور → دخول تلقائي لعيادته |
| التطوير (بدون wildcard DNS) | المطورون والاختبارات | `http://localhost:3000/?org=<slug>` لعيادة، و `?platform=1` للوحة Super Admin، والجذر بدونهما = الموقع الرئيسي. يُحفظ الاختيار في `sessionStorage` ويُرسل للخادم كترويسة `X-Org-Slug` |
| رابط إعادة تعيين كلمة المرور | أي مستخدم | `https://clinicsyseg.com/?reset=<token>` → كلمة مرور جديدة → شاشة الدخول |
| `POST /api/webhooks/<name>` (لا شاشة) | مزوّد خارجي (لا أحد اليوم) | حدث موقّع يُقبل مرة واحدة ويُعالج في الخلفية؛ لا يعمل إلا لمزوّد له `WEBHOOK_<NAME>_SECRET` (S10) |
| `?import=1` (مؤقت) | موظفو العيادة | صفحة إدخال سجلات المرضى الورقية القديمة. ملفها يُحمّل عند فتح الرابط فقط؛ تظهر «جارٍ التحقق من الجلسة والصلاحيات…» ثم الصفحة أو شاشة الدخول. عند فشل التحميل: Toast «تعذّر تحميل صفحة الاستيراد — تحقق من الاتصال» |

## Primary journey

### J1 — Super Admin ينشئ عيادة

`A02 قائمة العيادات` → «إنشاء عيادة» → `A03 خطوة 1: الاسم + slug` → `خطوة 2: التخصص (تُحدد الميزات الافتراضية تلقائيًا، قابلة للتعديل)` → `خطوة 3: الخطة والحالة` → `خطوة 4: بريد أول مدير` → «إنشاء» → **نجاح:** ملخص يعرض الرابط `ahmad.clinicsyseg.com` وحالة «بانتظار التفعيل» ودعوة مرسلة.

### J2 — أول دخول لمدير العيادة

بريد الدعوة → `S03 قبول الدعوة` → تعيين كلمة المرور → تفعيل العضوية والعيادة → `C01 لوحة اليوم` → شريط «ابدأ الإعداد» (الفرع الأول، دعوة الموظفين، الإعدادات).

### J3 — دخول مستخدم عادي

`S01` → `S02 الدخول` → تحقق الهوية → جلب العضويات النشطة في عيادات نشطة:
- عضوية واحدة → تحويل إلى `{slug}.clinicsyseg.com` → `C01`.
- أكثر من واحدة → `S04 اختيار العيادة` → `C01`.
- لا شيء → `S06 لا عضوية`.

### J4 — موظف الاستقبال يحجز موعدًا

`C03 التقويم (الفرع الحالي)` → «حجز» → اختيار/إنشاء مريض → القسم/الطبيب/المعالج → التاريخ والوقت → «حفظ» → **نجاح:** الموعد في التقويم + خيار تذكير واتساب.

## Navigation rules

- **المنصة:** شريط علوي فيه شعار ClinicSystem EG + دخول.
- **العيادة:** قائمة جانبية على اليمين (RTL) بالوحدات المفعلة؛ شريط علوي: اسم العيادة، محدد الفرع، قائمة المستخدم (الملف، تبديل العيادة، خروج).
- **Super Admin:** قائمة جانبية: المؤشرات، العيادات، التخصصات والوحدات، الخطط، السجل.
- **الرجوع:** زر رجوع المتصفح يعمل في كل الشاشات (مسارات URL حقيقية، مثل `/patients/:id`).
- **Deep links:** `{slug}.clinicsyseg.com/patients/P-102` → إن لم يكن مسجلًا: الدخول ثم العودة لنفس المسار بعد التحقق من العضوية.
- **رابط عيادة أخرى:** إن فتح المستخدم رابط عيادة ليس عضوًا فيها → `S06 لا عضوية` (لا بيانات، ولا كشف بوجود العيادة من عدمه).

## Empty and blocked states

| الحالة | ما يظهر |
|---|---|
| لا مرضى/مواعيد/فواتير | رسم بسيط + جملة توضيحية + زر الإجراء الأول (مثل «أضف أول مريض») |
| لا فروع | «أضف أول فرع لبدء الحجز» — الحجز معطل حتى وجود فرع |
| صلاحية مرفوضة | «ليست لديك صلاحية لهذه الصفحة» + رجوع للوحة اليوم |
| وحدة معطلة (رابط مباشر) | «هذه الميزة غير مفعلة لعيادتك» |
| عيادة موقوفة | «هذه العيادة متوقفة حاليًا. تواصل مع إدارة المنصة.» — لا بيانات |
| رابط غير موجود | «لا توجد عيادة بهذا الرابط» + رابط الموقع الرئيسي |
| انقطاع الاتصال | شريط «لا يوجد اتصال» وتعطيل أزرار الحفظ؛ لا عمل دون اتصال في الإصدار الأول. أول «تصدير Excel» في الزيارة وصفحة `?import=1` يحتاجان اتصالًا لتحميل ملفاتهما |
| أثناء تحميل البيانات بعد الدخول | الواجهة تظهر فورًا، والبيانات تُستبدل عند وصولها (كل الجداول تُطلب بالتوازي) |
| انتهاء الجلسة | تحويل للدخول مع العودة للمسار نفسه بعده |

## First-use journey

1. Super Admin ينشئ العيادة (J1) → دعوة لأول مدير.
2. المدير يقبل الدعوة (J2) ويعيّن كلمة المرور.
3. قائمة إعداد البداية (Onboarding checklist) في لوحة اليوم:
   - [ ] أضف أول فرع (اسم، عنوان، هاتف، ساعات العمل).
   - [ ] راجع إعدادات العيادة (اسم العرض، ساعات التقويم).
   - [ ] أضف الأقسام/الأطباء/المعالجين.
   - [ ] ادعُ فريقك (استقبال، أطباء، معالجين) وحدد فروعهم.
   - [ ] أضف أول مريض واحجز أول موعد.
4. تختفي القائمة بعد إكمال الخطوات أو عند الضغط على «إخفاء».

**المنفذ ✅ («ابدأ الإعداد» على C01 لمدير العيادة فقط، لا في وضع العرض):** كل خطوة تُعلَّم تلقائيًا من بيانات العيادة: «أكمل بيانات الفرع الأول» (فرع نشط له عنوان أو هاتف — كل عيادة تُنشأ بالفرع الرئيسي)، «راجع إعدادات العيادة» (هاتف أو بريد أو عنوان)، «أضف الأقسام والأطباء والأخصائيين» (طبيب أو أخصائي في القائمة)، «ادعُ فريقك» (أكثر من عضو أو دعوة معلقة، عند تفعيل `core.staff`)، «أضف أول مريض واحجز أول موعد». كل خطوة تفتح شاشتها (C07، أو تبويب C08، أو C06، أو C03). «لاحقًا» يطويها إلى سطر «ابدأ الإعداد — أنجزت X من Y» مع «متابعة الإعداد» لهذا التبويب فقط؛ «إخفاء» أو إكمال كل الخطوات يزيلها نهائيًا لهذا المدير في هذه العيادة.

## سلوك الـ API المنفذ لهذه الشاشات (Milestone 2)

الشاشات نفسها في Milestone 3، والسلوك التالي جاهز ومُختبر في الـ API:

- **S03 قبول الدعوة:** وضعان حسب `account_exists` من `GET /api/invitations/:token`: حساب جديد (الاسم + كلمة المرور)، أو حساب موجود (كلمة مروره فقط). الأخطاء: `410` مستخدمة/منتهية/ملغاة، و `403` عيادة غير نشطة. بعد القبول يُسجَّل الدخول، وأول مدير يفعّل العيادة.
- **C06 الموظفون والدعوات:** حالات الدعوة `pending` / `expired` / `accepted` / `revoked`؛ إعادة الإرسال للمعلقة والمنتهية؛ الإلغاء = `revoked`؛ «عضو بالفعل» = `409 already_member`؛ حد المستخدمين = `422`. `email_sent: false/null` يعني أن البريد لم يُرسل بعد، فتُعرض إعادة الإرسال.
- **A03 إنشاء عيادة:** عملية ذرية → `pending_activation` + «الفرع الرئيسي» + بريد دعوة لأول مدير.
- **A04 الحالة:** السبب إلزامي للإيقاف والإغلاق؛ الإيقاف يضبط الاحتفاظ 6 أشهر؛ إعادة التفعيل تمسحه. الانتقالات: `draft → pending_activation → active ⇄ suspended → closed`.
- **دخول المنصة في التطوير:** `?platform=1` → الترويسة `X-Platform: 1`.

**تم إصلاح** الفروقات التي ذُكرت هنا (الواجهة الفارغة بعد الدخول، ودخول غير الأعضاء والمعطلين) في المهمة 3.2.

## الشاشات المنفذة (Milestone 3)

**مداخل العيادة والمنصة (المهام 3.1–3.5)** — `e2e/tenant.spec.cjs`:
- **S01/S02/S04 (الجذر):** عضوية واحدة → العيادة مباشرة؛ أكثر → بطاقات الاختيار (الاسم، شارة التخصص، الدور، الرابط)؛ لا شيء → S06. Super Admin بلا عضوية يرى رابط المنصة.
- **S06:** «لا توجد عيادة بهذا الرابط»، «العيادة متوقفة»، «بانتظار التفعيل»، «لا عضوية»، «لا عيادة»، خطأ شبكة مع «إعادة المحاولة»، وحالات الدعوة (مستخدمة/منتهية/ملغاة/غير موجودة/العيادة غير نشطة).
- **الدخول:** أخطاء مضمنة فوق النموذج (`role=alert`) بدل Toast؛ رفض غير الأعضاء والمعطلين مع تسجيل الخروج؛ «أبقني مسجلًا» = 30 يومًا. بطاقة «حجز الضيف» ورابط المبيعات يظهران في وضع العرض فقط.
- **S03 والتعيين:** كما في «سلوك الـ API المنفذ» أعلاه؛ صفحات الدعوة المنتهية تطلب التواصل مع مدير العيادة (لا زر «اطلب دعوة جديدة»؛ PRD سؤال 13).
- **التبديل:** «تبديل العيادة» زر في بطاقة المستخدم في الشريط الجانبي (عند وجود أكثر من عضوية)؛ محدد الفرع يعرض الفروع المسموحة فقط ويعيد تحميل بيانات الفرع.
- **الوحدات:** عناصر القائمة ولوحة الأوامر تختفي للوحدات المعطلة؛ الرابط المباشر يعرض «هذه الميزة غير مفعلة لعيادتك» مع «العودة إلى لوحة التحكم». الربط: patients → `core.patients`، appointments → `core.appointments`، payments و packages → `core.billing`، reports → `core.reports`، settings → `core.settings`، sessions → `physio.sessions`، treatments → `physio.treatment_plans`.
- **فروق عن هذا المستند:** الرابط غير المسموح للدور يعود للصفحة الرئيسية بدل صفحة «ليست لديك صلاحية» (المهمة 3.11)؛ الروابط بالـ hash لا بمسارات حقيقية؛ دور `staff` بلا واجهة (PRD سؤال 14).

**لوحة Super Admin (المهمة 3.6)** — `e2e/platform.spec.cjs`:
- **بوابة الجلسة:** دخول، أو «غير مصرح» مع خروج، أو «افتح من عنوان الإدارة» (`platform_required`)، أو خطأ مع إعادة المحاولة، أو انتهاء الجلسة مع إشعار.
- **A03:** فحص الـ slug محليًا ثم عبر الـ API بعد 400 ms مع إعادة المحاولة؛ التخصص المختار افتراضيًا هو صاحب أكثر الوحدات المتاحة؛ «تفعيلها كلها معًا» لحل التبعيات؛ منع عدم التطابق بين الخطة والوحدات؛ تأكيد التجاهل حتى مع زر الرجوع.
- **A04:** إجراءات الحالة تشمل «تفعيل يدويًا» (`pending_activation → active`)؛ تغيير التخصص يعرض فرق الوحدات قبل الحفظ؛ تعطيل وحدة يطلب تأكيدًا.
- **A01/A02:** بطاقة «تجاوزت مدة الاحتفاظ» تفتح العيادات الموقوفة؛ صفوف العيادات الموقوفة تعرض تاريخ الاحتفاظ. **A05** للقراءة فقط (المهمة 4.1). **A07** فلتر العيادات يعرض أحدث 200 عيادة.

## الشاشات المنفذة (Milestone 3 — المرحلة الثانية)

**C07 الفروع ✅** (`#/branches`، في مجموعة «النظام»، لـ `admin` فقط، الوحدة `core.branches`؛ وأيضًا «إدارة الفروع» من محدد الفرع): بطاقات (الاسم، شارة نشط/معطّل، «الفرع الحالي»، العنوان، الهاتف، الغرف، عدد الموظفين، ساعات العمل مجمّعة)؛ نموذج إضافة/تعديل (اسم إلزامي وفريد، عنوان، هاتف، غرف، ساعات لكل يوم)؛ **«تعطيل فرع» و«إعادة تفعيل فرع» بتأكيد، ولا حذف أبدًا**؛ لا يمكن تعطيل آخر فرع نشط؛ «الفروع النشطة: X من Y» وتنبيه عند الحد؛ رسالة حد الخطة عند الإضافة وإعادة التفعيل. الفرع المعطّل يخرج من المحدد وتبقى بياناته؛ العضو الذي لم يبق له إلا فرع معطّل يرى بياناته مع شريط تنبيه ولا يستطيع حجزًا جديدًا (في الواجهة فقط — المهمة 3.18).

**C06 المستخدمون والأدوار ✅** (تبويب الإعدادات، لـ `admin`، يختفي إذا عُطّلت `core.staff`): جدولان بدل جدول واحد — **«أعضاء العيادة»** (الاسم والبريد، الدور، الفروع، الحالة، وقائمة ⋯: تعديل الدور والفروع، تعديل الاسم، إعادة تعيين كلمة المرور، تعطيل/إعادة تفعيل، نسخ البريد) و **«الدعوات»** (المدعو، الحالة، الانتهاء، «إعادة الإرسال» و«إلغاء» بتأكيد، وفلتر «بانتظار القبول / كل الدعوات»). ✅ حالة البريد من الخادم (`email_status`، المهمة 3.15): شارة حمراء «لم يُرسل البريد» عند `failed`، وشارة محايدة «البريد قيد الإرسال» عند `pending`، ولا شيء عند `sent` أو للدعوات الأقدم؛ تظهر لكل المديرين وفي تبويب «الأعضاء» في A04 أيضًا، وتُحدَّث القائمة بعد الإنشاء أو إعادة الإرسال وكل 15 ثانية ما دامت دعوة قيد الإرسال. العداد «المستخدمون: X من Y (منها دعوات معلّقة: n)». «إنشاء مستخدم» ما زال يعمل ويطلب الفروع للأدوار غير `admin`.

**ملف المريض والتشخيص حسب التخصص (`0018`):** ملف المريض يتبع نموذج تشخيص العيادة (`diagnosis_form` لتخصصها، يختاره Super Admin): **العلاج الطبيعي** الملف الحالي + تبويب «التشخيص» (للمدير والطبيب والأخصائي فقط، لا يظهر للاستقبال): مخطط الجسم بنقاط الألم المحفوظة لآخر تشخيص، وقائمة التشخيصات السابقة لاختيار أحدها، وحقوله؛ «تشخيص جديد» يفتح نموذج التشخيص للمريض نفسه (والأخصائي يصل إليه من هنا، فليست له صفحة «خطط العلاج»). **نموذج التشخيص (العلاج الطبيعي):** يُحفظ في قاعدة البيانات لا في المتصفح؛ يبدأ من آخر تشخيص للمريض («بدأ النموذج من آخر تشخيص…»)، و«حفظ التشخيص» يضيف سجلًا بتاريخ اليوم ثم «حفظ التعديلات» يعدّله نفسه؛ مسودة قديمة على الجهاز تُعرض أولًا («مسودة محفوظة على هذا الجهاز فقط…») وتنتقل إلى الملف عند الحفظ. الأخطاء: «السجل السريري للطبيب والأخصائي والمدير فقط»، «بعض البيانات غير صالحة…». **الأسنان والعام:** CR3 و CR4.

**فتح ملف مريض وطباعة إيصال (المراجعة الأمنية):** «فتح» و«تنزيل» في ملفات المريض يفتحان رابطًا موقّعًا من الخادم، أو `file_url` إن كان http(s) أو مسارًا في الموقع؛ أي رابط آخر لا يُفتح ويظهر «لا يوجد ملف متاح للعرض». نافذة الطباعة (الإيصال) تطبع تلقائيًا، وزر «طباعة / حفظ PDF» فيها يعمل تحت سياسة CSP. تسجيل الدفع لا يطلب من المتصفح عنوان IP: الخادم يسجله.

**البيانات الأقدم من 180 يومًا ✅ (S9):** عند البدء تُقرأ آخر 180 يومًا والقادم (والفواتير غير المسددة كلها، والحجوزات والجلسات بلا تاريخ)؛ ما قبلها يُقرأ حين تعرضه شاشة: **ملف المريض** يقرأ سجل المريض كله عند فتحه («جارٍ تحميل السجل الأقدم…» ثم يظهر في «السجل» و«الجلسات» و«الفواتير»)، و**C05 التقارير** تقرأ ما قبل النافذة حين يسبقها تاريخ «من» («جارٍ تحميل الفترة الأقدم…»؛ «من» فارغ = كل الفترة)، و**C03 التقويم** يقرأ حجوزات اليوم أو الأسبوع المعروض إن كان أقدم. ما قُرئ يبقى حتى تغيير الفرع. الخطأ: «تعذّر تحميل البيانات الأقدم» مع «إعادة المحاولة» في التقارير. الشاشات بلا فترة (قائمة المواعيد، توزيع طرق الدفع) تعرض النافذة. «أضف أول مريض واحجز أول موعد» في «ابدأ الإعداد» تعدّ الحجوزات الأقدم أيضًا.

**C03 و C05 بالفرع:** المواعيد والتقارير تقرأ صفوف الفرع المختار، وصفحة التقارير تسمّيه. ✅ **«كل الفروع» للمدير** (المهمة 3.19): في عيادة بأكثر من فرع يظهر للمدير زران «الفرع الحالي» / «كل الفروع». في «كل الفروع» تشمل الإجماليات كل الفروع، ويُضاف عمود «الفرع» إلى الجدول وتصدير Excel، وبطاقة «حسب الفرع» (صف لكل فرع، والمعطّل بشارة «معطّل»، وصف «الإجمالي»)، والبحث يطابق اسم الفرع. الاختيار يبقى عند التنقل بين التبويبات (المالية، الطبية، التشغيلية) ولا يغيّر الفرع المستخدم. الأدوار الأخرى كما هي.

**الحجز والدفع المتزامنان (S4 ✅):** موظفان يؤكدان نفس الأخصائي/الطبيب والتاريخ والوقت → يُحفظ الأول، والثاني يرى «هذا الموعد محجوز بالفعل — اختر وقتًا آخر» ويخرج الحجز من تقويمه وتُعاد قراءة بيانات العيادة. «تأكيد» الدفع السريع مرتين أو إعادته بعد انقطاع → دفعة واحدة وإيصال واحد (نفس المفتاح لكل محاولة حتى تنجح).

**بريد لم يُرسل (S7 ✅):** دعوة أو رابط استعادة فشل إرسالهما (شارة «لم يُرسل البريد» في C06 و A04) يُعاد إرسالهما تلقائيًا بعد دقيقة ثم بفترات متزايدة (حتى 5 محاولات)، برابط جديد؛ «إعادة الإرسال» اليدوية تبقى متاحة وتلغي الحاجة للمحاولة الآلية.

**خطأ في صفحة (S6 ✅):** صفحة يحدث فيها خطأ أثناء العرض تُستبدل ببطاقة «حدث خطأ في هذه الصفحة» داخل الواجهة (القائمة تبقى) مع «إعادة المحاولة»؛ الانتقال إلى صفحة أخرى يزيلها. الخطأ يُرسل مرة في الدقيقة على الأكثر، ولا يُرسل شيء في وضع العرض.

**فرع معطّل (3.18):** أي إضافة على فرع معطّل (حجز، فاتورة، دفعة سريعة...) يرفضها الخادم برسالة «هذا الفرع معطّل — اختر فرعًا نشطًا لإضافة حجوزات أو مدفوعات جديدة»؛ تعديل السجلات القديمة وقراءتها مسموحان. محدد الفرع لا يختار فرعًا معطّلًا تلقائيًا ما دام هناك فرع نشط.

**الرحلات J1–J4 ✅** في `e2e/journeys.spec.cjs`. J4 عبر «حجز جديد» (مريض → أخصائي → طبيب اختياري → تاريخ → وقت → «تأكيد الحجز»): يُحفظ في الفرع الحالي ويظهر في التقويم، مع تذكير واتساب في تفاصيل الحجز. **تعطيل وحدة** يرفض الـ API عملياتها أيضًا (`403`).

## سلوك لوحة المفاتيح والجوال (مراجعة 3.10)

- **رابط «تخطَّ إلى المحتوى»** أول نقطة Tab في واجهة العيادة، ينقل إلى المحتوى الرئيسي.
- **C03:** حجز التقويم يُفتح بـ Enter أو Space (التفاصيل)؛ «نقل / تعديل» من التفاصيل يفتح إعادة الجدولة، وعند الإغلاق يعود التركيز إلى الحجز.
- **قائمة «⋯» في الصفوف:** الفتح ينقل التركيز إلى أول عنصر؛ ↑/↓ للتنقل؛ Esc أو Tab يغلقان ويعيدان إلى الزر.
- **لوحة الأوامر:** ↑/↓ لاختيار نتيجة، Enter للفتح، Esc للإغلاق والعودة إلى زر البحث.
- **كل النوافذ** (بما فيها إعادة الجدولة وحجز المريض التجريبي ولوحة الأوامر): Tab لا يخرج منها، و Esc يغلق العليا، والتركيز يعود لمن فتحها.
- **الجوال:** قائمة المرضى تبدأ بعرض البطاقات؛ نماذج الدخول تظهر في الشاشة الأولى؛ Esc يغلق الدرج.
- **إضافة مريض:** الجنس يُحفظ `F` / `M` (كما في التعديل والاستيراد وفلتر المرضى)؛ الصفوف القديمة `Female` / `Male` تُعرض «أنثى» / «ذكر».
- ✅ **صفحة «ليست لديك صلاحية لهذه الصفحة»** (المهمة 3.11): رابط صفحة غير مسموحة للدور (مثل الاستقبال ← `#/settings`) يعرض الصفحة مع السبب وزر «العودة إلى …» لصفحة الدور الرئيسية، ويبقى العنوان كما طُلب، بدل العودة الصامتة للوحة التحكم.

## اللغة (العربية / English)

- **أين يُغيَّر:** زر واحد يسمّي اللغة الأخرى («English» / «العربية») في زاوية كل شاشات الدخول (S02، S03، S04، S06، الاستعادة، دخول الموقع الرئيسي، دخول المنصة)، وفي الشريط العلوي لتطبيق العيادة ولوحة المنصة («EN» / «ع» على الجوال)، وفي صفحة الاستيراد وبوابة المريض التجريبية.
- **ماذا يحدث:** تُحفظ اللغة وتُعاد الصفحة نفسها (نفس العنوان والصفحة) باللغة الجديدة واتجاهها؛ النوافذ المفتوحة تُغلق. الرابط `?lang=en` أو `?lang=ar` يفرض لغة ويحفظها.
- **تبقى اللغة** بعد إعادة التحميل والخروج والدخول، وعند الانتقال بين الموقع الرئيسي ولوحة المنصة وروابط العيادات.
- **رسائل البريد** (الدعوة واستعادة كلمة المرور) بلغتين دائمًا، ولغة من أرسلها أولًا.
