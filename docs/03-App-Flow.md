## Entry points

| نقطة الدخول | من يستخدمها | ما يحدث |
|---|---|---|
| `https://clinicsyseg.com/` | كل المستخدمين | الموقع الرئيسي: تعريف مختصر + زر «تسجيل الدخول» + توضيح أن النظام يعمل بدعوة فقط |
| `https://{slug}.clinicsyseg.com/` | موظفو عيادة | تحل الواجهة الـ slug؛ إن لم يكن مسجلًا تظهر صفحة الدخول باسم العيادة |
| `https://admin.clinicsyseg.com/` | Super Admin فقط | لوحة إدارة المنصة بعد مصادقة قوية |
| رابط الدعوة في البريد | مستخدم مدعو | `https://<slug>.clinicsyseg.com/?invite=<token>` → S03 تعيين الاسم وكلمة المرور → دخول تلقائي لعيادته |
| التطوير (بدون wildcard DNS) | المطورون والاختبارات | `http://localhost:3000/?org=<slug>` لعيادة، و `?platform=1` للوحة Super Admin، والجذر بدونهما = الموقع الرئيسي. يُحفظ الاختيار في `sessionStorage` ويُرسل للخادم كترويسة `X-Org-Slug` |
| رابط إعادة تعيين كلمة المرور | أي مستخدم | `https://clinicsyseg.com/?reset=<token>` → كلمة مرور جديدة → شاشة الدخول |
| `?import=1` (مؤقت) | موظفو العيادة | صفحة إدخال سجلات المرضى الورقية القديمة. ملفها يُحمّل عند فتح الرابط فقط؛ تظهر «جارٍ التحقق من الجلسة والصلاحيات…» ثم الصفحة أو شاشة الدخول. عند فشل التحميل: Toast «تعذّر تحميل صفحة الاستيراد — تحقق من الاتصال» |

## Primary journey

### J1 — Super Admin ينشئ عيادة

`A02 قائمة العيادات` → «إنشاء عيادة» → `A03 خطوة 1: الاسم + slug` → `خطوة 2: التخصص (تُحدد الميزات الافتراضية تلقائيًا، قابلة للتعديل)` → `خطوة 3: الخطة والحالة` → `خطوة 4: بريد أول مدير` → «إنشاء» → **نجاح:** ملخص يعرض الرابط `ahmad.clinicsyseg.com` وحالة «بانتظار التفعيل» ودعوة مرسلة.

### J2 — أول دخول لمدير العيادة

بريد الدعوة → `S03 قبول الدعوة` → تعيين كلمة المرور → تفعيل العضوية والعيادة → `C01 لوحة اليوم` → شريط «ابدأ الإعداد» (الفرع الأول، دعوة الموظفين، الإعدادات).

### J3 — دخول مستخدم عادي

`S01` → `S02 الدخول` → تحقق الهوية → جلب العضويات النشطة في عيادات نشطة:
- عضوية واحدة → تحويل إلى `{slug}.clinicsyseg.com` → `C01`.
- أكثر من واحدة → `S04 اختيار العيادة` → `C01`.
- لا شيء → `S06 لا عضوية`.

### J4 — موظف الاستقبال يحجز موعدًا

`C03 التقويم (الفرع الحالي)` → «حجز» → اختيار/إنشاء مريض → القسم/الطبيب/المعالج → التاريخ والوقت → «حفظ» → **نجاح:** الموعد في التقويم + خيار تذكير واتساب.

## Navigation rules

- **المنصة:** شريط علوي فيه شعار ClinicSystem EG + دخول.
- **العيادة:** قائمة جانبية على اليمين (RTL) بالوحدات المفعلة؛ شريط علوي: اسم العيادة، محدد الفرع، قائمة المستخدم (الملف، تبديل العيادة، خروج).
- **Super Admin:** قائمة جانبية: المؤشرات، العيادات، التخصصات والوحدات، الخطط، السجل.
- **الرجوع:** زر رجوع المتصفح يعمل في كل الشاشات (مسارات URL حقيقية، مثل `/patients/:id`).
- **Deep links:** `{slug}.clinicsyseg.com/patients/P-102` → إن لم يكن مسجلًا: الدخول ثم العودة لنفس المسار بعد التحقق من العضوية.
- **رابط عيادة أخرى:** إن فتح المستخدم رابط عيادة ليس عضوًا فيها → `S06 لا عضوية` (لا بيانات، ولا كشف بوجود العيادة من عدمه).

## Empty and blocked states

| الحالة | ما يظهر |
|---|---|
| لا مرضى/مواعيد/فواتير | رسم بسيط + جملة توضيحية + زر الإجراء الأول (مثل «أضف أول مريض») |
| لا فروع | «أضف أول فرع لبدء الحجز» — الحجز معطل حتى وجود فرع |
| صلاحية مرفوضة | «ليست لديك صلاحية لهذه الصفحة» + رجوع للوحة اليوم |
| وحدة معطلة (رابط مباشر) | «هذه الميزة غير مفعلة لعيادتك» |
| عيادة موقوفة | «هذه العيادة متوقفة حاليًا. تواصل مع إدارة المنصة.» — لا بيانات |
| رابط غير موجود | «لا توجد عيادة بهذا الرابط» + رابط الموقع الرئيسي |
| انقطاع الاتصال | شريط «لا يوجد اتصال» وتعطيل أزرار الحفظ؛ لا عمل دون اتصال في الإصدار الأول. أول «تصدير Excel» في الزيارة وصفحة `?import=1` يحتاجان اتصالًا لتحميل ملفاتهما |
| أثناء تحميل البيانات بعد الدخول | الواجهة تظهر فورًا، والبيانات تُستبدل عند وصولها (كل الجداول تُطلب بالتوازي) |
| انتهاء الجلسة | تحويل للدخول مع العودة للمسار نفسه بعده |

## First-use journey

1. Super Admin ينشئ العيادة (J1) → دعوة لأول مدير.
2. المدير يقبل الدعوة (J2) ويعيّن كلمة المرور.
3. قائمة إعداد البداية (Onboarding checklist) في لوحة اليوم:
   - [ ] أضف أول فرع (اسم، عنوان، هاتف، ساعات العمل).
   - [ ] راجع إعدادات العيادة (اسم العرض، ساعات التقويم).
   - [ ] أضف الأقسام/الأطباء/المعالجين.
   - [ ] ادعُ فريقك (استقبال، أطباء، معالجين) وحدد فروعهم.
   - [ ] أضف أول مريض واحجز أول موعد.
4. تختفي القائمة بعد إكمال الخطوات أو عند الضغط على «إخفاء».

## سلوك الـ API المنفذ لهذه الشاشات (Milestone 2)

الشاشات نفسها في Milestone 3، والسلوك التالي جاهز ومُختبر في الـ API:

- **S03 قبول الدعوة:** وضعان حسب `account_exists` من `GET /api/invitations/:token`: حساب جديد (الاسم + كلمة المرور)، أو حساب موجود (كلمة مروره فقط). الأخطاء: `410` مستخدمة/منتهية/ملغاة، و `403` عيادة غير نشطة. بعد القبول يُسجَّل الدخول، وأول مدير يفعّل العيادة.
- **C06 الموظفون والدعوات:** حالات الدعوة `pending` / `expired` / `accepted` / `revoked`؛ إعادة الإرسال للمعلقة والمنتهية؛ الإلغاء = `revoked`؛ «عضو بالفعل» = `409 already_member`؛ حد المستخدمين = `422`. `email_sent: false/null` يعني أن البريد لم يُرسل بعد، فتُعرض إعادة الإرسال.
- **A03 إنشاء عيادة:** عملية ذرية → `pending_activation` + «الفرع الرئيسي» + بريد دعوة لأول مدير.
- **A04 الحالة:** السبب إلزامي للإيقاف والإغلاق؛ الإيقاف يضبط الاحتفاظ 6 أشهر؛ إعادة التفعيل تمسحه. الانتقالات: `draft → pending_activation → active ⇄ suspended → closed`.
- **دخول المنصة في التطوير:** `?platform=1` → الترويسة `X-Platform: 1`.

**تم إصلاح** الفروقات التي ذُكرت هنا (الواجهة الفارغة بعد الدخول، ودخول غير الأعضاء والمعطلين) في المهمة 3.2.

## الشاشات المنفذة (Milestone 3)

**مداخل العيادة والمنصة (المهام 3.1–3.5)** — `e2e/tenant.spec.cjs`:
- **S01/S02/S04 (الجذر):** عضوية واحدة → العيادة مباشرة؛ أكثر → بطاقات الاختيار (الاسم، شارة التخصص، الدور، الرابط)؛ لا شيء → S06. Super Admin بلا عضوية يرى رابط المنصة.
- **S06:** «لا توجد عيادة بهذا الرابط»، «العيادة متوقفة»، «بانتظار التفعيل»، «لا عضوية»، «لا عيادة»، خطأ شبكة مع «إعادة المحاولة»، وحالات الدعوة (مستخدمة/منتهية/ملغاة/غير موجودة/العيادة غير نشطة).
- **الدخول:** أخطاء مضمنة فوق النموذج (`role=alert`) بدل Toast؛ رفض غير الأعضاء والمعطلين مع تسجيل الخروج؛ «أبقني مسجلًا» = 30 يومًا. بطاقة «حجز الضيف» ورابط المبيعات يظهران في وضع العرض فقط.
- **S03 والتعيين:** كما في «سلوك الـ API المنفذ» أعلاه؛ صفحات الدعوة المنتهية تطلب التواصل مع مدير العيادة (لا زر «اطلب دعوة جديدة»؛ PRD سؤال 13).
- **التبديل:** «تبديل العيادة» زر في بطاقة المستخدم في الشريط الجانبي (عند وجود أكثر من عضوية)؛ محدد الفرع يعرض الفروع المسموحة فقط ويعيد تحميل بيانات الفرع.
- **الوحدات:** عناصر القائمة ولوحة الأوامر تختفي للوحدات المعطلة؛ الرابط المباشر يعرض «هذه الميزة غير مفعلة لعيادتك» مع «العودة إلى لوحة التحكم». الربط: patients → `core.patients`، appointments → `core.appointments`، payments و packages → `core.billing`، reports → `core.reports`، settings → `core.settings`، sessions → `physio.sessions`، treatments → `physio.treatment_plans`.
- **فروق عن هذا المستند:** الرابط غير المسموح للدور يعود للصفحة الرئيسية بدل صفحة «ليست لديك صلاحية» (المهمة 3.11)؛ الروابط بالـ hash لا بمسارات حقيقية؛ دور `staff` بلا واجهة (PRD سؤال 14).

**لوحة Super Admin (المهمة 3.6)** — `e2e/platform.spec.cjs`:
- **بوابة الجلسة:** دخول، أو «غير مصرح» مع خروج، أو «افتح من عنوان الإدارة» (`platform_required`)، أو خطأ مع إعادة المحاولة، أو انتهاء الجلسة مع إشعار.
- **A03:** فحص الـ slug محليًا ثم عبر الـ API بعد 400 ms مع إعادة المحاولة؛ التخصص المختار افتراضيًا هو صاحب أكثر الوحدات المتاحة؛ «تفعيلها كلها معًا» لحل التبعيات؛ منع عدم التطابق بين الخطة والوحدات؛ تأكيد التجاهل حتى مع زر الرجوع.
- **A04:** إجراءات الحالة تشمل «تفعيل يدويًا» (`pending_activation → active`)؛ تغيير التخصص يعرض فرق الوحدات قبل الحفظ؛ تعطيل وحدة يطلب تأكيدًا.
- **A01/A02:** بطاقة «تجاوزت مدة الاحتفاظ» تفتح العيادات الموقوفة؛ صفوف العيادات الموقوفة تعرض تاريخ الاحتفاظ. **A05** للقراءة فقط (المهمة 4.1). **A07** فلتر العيادات يعرض أحدث 200 عيادة.
