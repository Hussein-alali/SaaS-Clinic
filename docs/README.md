## التغييرات في الإصدار 1.1 من BRD (21 أكتوبر 2026)

- **الفروع** أصبحت ضمن النواة المشتركة في **كل التخصصات** (العلاج الطبيعي، طب الأسنان، الطب العام)، وليس العلاج الطبيعي فقط.
- **النطاق الأساسي المعتمد:** `clinicsyseg.com`، وروابط العيادات مثل `ahmad.clinicsyseg.com`.
- **دعوة الموظفين:** مدير العيادة يدعو موظفيه بنفسه ضمن صلاحياته، وإنشاء العيادات يبقى حكرًا على Super Admin.
- **التخصص:** تخصص رئيسي واحد لكل عيادة أولًا، مع تصميم يسمح بالتوسع.
- **الاشتراك:** إدارة يدوية من لوحة Super Admin في البداية.
- **حدود الخطط:** تُحدد تجاريًا، والنظام يدعم ضبطها لكل خطة.
- **العيادات المتوقفة:** تبقى بياناتها محفوظة 6 أشهر.

**ما زال مفتوحًا:** الشعار والألوان لكل عيادة؛ ماذا يحدث بعد الـ 6 أشهر وطريقة التصدير والاستعادة؛ نطاق وحدات الأسنان والطب العام وصاحب الاعتماد السريري.

## طريقة الاستخدام مع أداة البرمجة بالذكاء الاصطناعي

1. ابدأ بالـ PRD؛ الوثائق الخمس الأخرى مبنية على ميزاته وقصصه.
2. أعطِ الوثائق الست معًا لأداة البرمجة، واطلب منها **الإشارة لأي تناقض** وحلّه قبل التنفيذ.
3. نفّذ حسب [خطة التنفيذ](06-Implementation-Plan.md) مرحلة مرحلة، ولا تنتقل لمرحلة قبل التحقق من معايير قبول المرحلة السابقة.
4. حدّث الوثائق كلما تغير التطبيق أو قرار.

> `PRD.md` في جذر المستودع يصف نظام «كينيتك» الحالي (عيادة واحدة). هذه الوثائق تصف التحول إلى منصة ClinicSystem EG متعددة العيادات.
